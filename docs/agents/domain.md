# Domain documentation

This repository uses a single domain context.

## Before exploring the codebase

- Read `GLOSSARY.md` at the repository root for agreed domain terms.
- Read the architecture decision records (ADRs) in `docs/adr/` that apply to the area under investigation.

If either location is absent, continue silently. `/domain-modeling`, reached through `/grill-with-docs` or `/improve-codebase-architecture`, creates these documents as terms and decisions are settled.

## Use the glossary

Use the glossary's terms in issue titles, proposals, hypotheses, and test names. When a concept has no entry, check whether an existing term covers it. If the gap is genuine, note it for `/domain-modeling`.

## Identify conflicts with decisions

When a proposal conflicts with an ADR, cite the record by number and title, identify the conflicting part of the proposal, and explain why the decision is worth revisiting.
